## 2. 지금 하지 않은 것과 이유(예전 기록 — 그림·성인 모드·본인인증 화면은 2026-11-08에 지움)

- **Next.js/React 전면 재작성(가이드 2-2, 3장, Phase 1·3)** — 배포 형태(claude.ai 아티팩트 단일 파일, 파일로 열어 쓰는 BYOK)가 바뀌어야 합니다. `<script type="module" src>`는 file://에서 막히므로, 나누더라도 **번들러로 다시 단일 index.html을 만드는 방식**이 먼저입니다(CLAUDE.md 원칙). 이번 작업에서는 파서·프롬프트 빌더를 DOM과 상관없는 순수 함수로 유지해, 나중에 `core/`로 옮기기 쉽게 했습니다.
- **백엔드(인증, 서버 원장, PG, 이미지 스토리지, 서버 측 buildInput — 4·5장, Phase 4·5)** — 서버가 있어야 합니다. 프론트는 프록시 연결 지점만 마련했습니다. **하트·PLUS·무료 턴은 여전히 데모**라 브라우저에서 조작할 수 있으므로, 실제 결제를 붙이기 전에 서버 원장이 반드시 먼저 있어야 합니다.
- **이미지 참조 캐싱(8-3)** — 이미지 엔진을 Runware(Pony Diffusion V6 XL, 글·태그로만 생성)로 바꾸면서 참고 그림을 보내지 않게 되어 해당 없음. 같은 인물을 더 정확히 맞추려면 나중에 서버 쪽에서 Runware의 이미지 참조 기능(IP-Adapter 등)을 검토. 2026-11-03부터는 출연진의 영문 태그(`cast[].tags`·`lookTags`)로 생김새를 고정하는 쪽을 먼저 씀.
- **그림 조합 코드(2026-11-03)** — 감정·의상·장소 조합 키 캐시(`[[img:코드:3,404,501]]`)와 대화 중 자동 생성까지 들어감(CLAUDE.md '그림 조합 코드'). 남은 것: 키워드북 항목의 `tags`(세계관 일러스트 영문 태그)는 칸만 만들고 비워 둠, 노골적인 코드 표(2xx·3xx)는 저장소에 넣지 않고 사용자가 '목록으로 추가'로 들여옴, 자동 생성은 응답당 최대 4장·조합당 한 번(Runware 장당 약 $0.0025)이라 서버 모드(serverKeys)에서는 요금 한도·생성 큐를 서버에 둘 것.
- **성인 모드와 무검열 모델 자동 우회(9장)** — 처음에는 반영하지 않았고, 이후 소유자 요청으로 **로컬 프로토타입 한정**으로 넣었습니다(브랜치 `feat/adult-mode-openrouter`). 범위와 경계:
  - 성인 서사는 OpenRouter 모델로만 보내고 Claude에는 성인 지시를 보내지 않음. claude.ai 아티팩트 안에서는 성인 모드 UI 자체가 꺼짐
  - 자동 우회는 성인 확인 + 토글 + OpenRouter 키일 때만. Claude의 위험 능력 분류기(cyber·bio·frontier_llm·reasoning_extraction) 거절과 미성년 암시가 있는 요청은 우회하지 않음. 그보다 먼저 Anthropic의 server-side fallback(다른 Claude 모델로 재시도)이 동작
  - 미성년 하드블록: `minorFlags`(작품 저장·공개) + `roomMinorHint`(대화·설정·유저노트·장기기억 — 성인 경로·거절 우회) + `minorHint`(그림 프롬프트) + Pony 네거티브 고정 + 성인 수위 그림 차단
  - **아직 출시 조건이 아님**: 지금 켜져 있는 성인 확인은 체크박스(자기 신고)입니다. 정식 서비스 전에 ① 휴대폰 본인인증 실제 채널 연결(아래 — 코드는 시험 모드까지 있음, 청소년유해매체물 제공 요건) ② 노골적 그림·글이 국내법상 음란물 배포에 해당하는지 법률 검토 ③ OpenRouter·각 모델 공급자·Runware 약관 확인이 필요합니다
- **휴대폰 본인인증(2026-11-05 사용자 요청 '실제로 휴대폰으로 성인인증' — 사용자가 '시험 모드부터'로 결정, 시험 모드까지 구현. 기본은 꺼짐, 켜는 순서는 SETUP.md)**. 조사 원문(출처 URL 포함)은 세션 공유 노트 `adult-verification-research.md`. 요점:
  - **필요한 것**: 본인인증 사업자와의 계약. 가장 가까운 길은 PortOne(포트원) V2 본인인증 + 채널(다날 휴대폰 본인인증·NHN KCP·KG이니시스 통합인증). 포트원 이용료는 무료 플랜이고, 다날은 월정액(2024-12 자료 기준 월 5만 원/1,200건부터, 통신사 심사 2~3주). **채널 계약에는 사업자등록증이 필요** — 개인(비사업자)은 실제 인증을 받을 수 없음. 통합인증의 네이버·토스·카카오 인증은 성인 업종이면 막힘, 다날·KCP의 'AI 성인 대화' 업종 심사는 신청 전에 문의해야 함
  - **지금(사업자 없이) 할 수 있는 것**: 포트원 콘솔 가입과 테스트 채널(KCP 테스트 MID — 임의 6자리로 통과하는 모의 인증, KG이니시스 테스트 MID)으로 흐름 전체를 만들고 시험. 다날은 테스트 연동 정보가 없음. 테스트로는 실제 통신사 인증·실제 CI·업종 심사를 확인할 수 없음
  - **구조(구현됨 — services/idv.js·ui/idv.js·docs/edge/verify-adult.ts)**: 브라우저는 SDK(`cdn.portone.io/v2/browser-sdk.js` — '외부 리소스는 Google Fonts만' 규칙의 예외가 됨)로 인증창만 열고(모바일은 redirectUrl로 돌아옴), **결과 확인은 Supabase Edge Function**이 API Secret(Supabase secrets — 저장소·앱에 넣지 않음)으로 `GET /identity-verifications/{id}`를 불러 `status === "VERIFIED"`·생년월일(연 나이 19세 기준)·인증 ID가 이 계정 것인지(함수가 번호를 만들어 계정에 묶음) 확인한 뒤, 클라이언트가 쓸 수 없는 표 `adult_checks`(select 본인만, 쓰기 권한 없음, 함수가 secret key로만 씀)에 성인 여부·확인 시각·만료일(1년)·시험 채널 여부만 저장. 이름·전화번호·생년월일·CI는 저장하지 않음. `ageOK()`는 자기 확인 대신 이 서버 값(1년이 지나면 다시 인증 — 청소년보호법 시행령 제17조 제2항)을 봄. privacy.html 수집 항목(생년월일·CI 해시 등)도 고쳐야 함
  - **안 되는 곳**: claude.ai 안(IN_CLAUDE)은 지금처럼 성인 모드 자체가 꺼짐. 파일(file://)로 열면 인증창이 돌아올 주소가 없으니 '웹 주소에서 인증' 안내 — 같은 계정으로 로그인했으면 서버의 인증 결과를 그대로 씀
  - **남은 일**: ① 실제 채널 계약(사업자등록) 뒤 `mode: "live"` ② **서버 판정** — 지금 판정(`ageOK`)은 브라우저 안의 일이라 콘솔로 고치면 넘어갈 수 있음. 서버가 AI를 부르는 단계에서 서버가 `adult_checks`를 보고 성인 경로를 정해야 진짜 관문 ③ 다날이면 `bypass.danal.AGELIMIT`·`CPTITLE`, 1인 다계정 확인이 필요해지면 CI의 HMAC 저장(처리방침 함께) ④ 실제 포트원 시험 채널로 한 번 끝까지 시험 — 지금까지는 가짜 SDK·가짜 API로만 시험함(시험 채널의 생년월일 값도 확인 전)
  - **법**: 청소년보호법 제16조(청소년유해매체물 제공 때 나이·본인 확인)의 확인 방법(시행령 제17조)에 자기 확인 체크는 들어 있지 않음. AI 대화가 이 의무 대상인지는 불분명해 법률 자문 권장 — 그 전까지 웹 주소의 성인 모드 공개 범위를 좁히는 것도 검토할 만함

```html
<script>
  window.HEARTVERSE_CONFIG = {
    anthropicUrl: "https://api.example.com/claude",  // Anthropic Messages API와 같은 요청·SSE 응답을 중계
```

## 6. 서버 프록시 요청 모양 참고(설계 — 2026-11-09)

4장의 프록시는 Anthropic 요청을 **그대로 중계**합니다(브라우저가 프롬프트를 조립). 다음 단계는 **서버가 프롬프트를 조립**하고 브라우저는 입력과 설정만 보내는 BFF입니다.

**참고 — 베이비챗 전송 API**(2026-11-09 탐방): `POST /ko/api/u/message/<charId>`, 본문 `{ prompt, roomId, proChatCount, isMultipleImage, model, outputLanguage, impersonation, memoryLimit, outputLevel, thinkingLevel, redo, enablePass }`, 응답은 `text/event-stream`(Vercel AI SDK 데이터 스트림 — start·start-step·text-start·text-delta). 서버가 캐릭터 설정·로어북·기억으로 프롬프트를 만들고, 브라우저에는 설정 원문이 내려오지 않습니다.

**우리 BFF가 받을 필드(후보)**:

| 필드 | 뜻 | 지금 코드의 출처 |
|---|---|---|
| `workId` | 작품 id | `room.char.id` |
| `roomId` | 대화방 id — 서버가 방의 메시지·상태창·장기기억·유저노트·페르소나를 가짐 | `room.id`(지금은 KV `room-<id>`가 계정 표에 통째로) |
| `model` | `lite`·`story`·`master` — 실제 모델 ID는 서버가 고름 | `room.set.model` → `ai/llm.js` MODEL_OF |
| `len` | 출력량 | `room.set.len` → `ai/models.js` LEN |
| `mem` | 기억력(턴) | `room.set.mem` |
| `text` | 유저 입력 원문(명령어 `!이름`도 그대로 — 연출 지시로 바꾸는 건 서버) | 입력창 → `core/commands.js` commandText |
| `redo` | 다시 쓰기면 대상 메시지 id와 방향 글 | `regen(i, direction)` |

**프롬프트 조립을 서버로 옮기면 바뀌는 것**:

- 순수 모듈은 서버(Edge Function)가 그대로 import할 수 있습니다 — `core/commands.js`·`images/codes.js`·`images/situations.js`·`ai/parse.js`·`ai/prompt/lore.js`(지금도 Node 단위 테스트가 바로 import). 프롬프트 조립 본체(`ai/prompt/rules.js`·`input.js`·`memory.js`)는 아직 브라우저 상태에 기댑니다 — `core/rooms.js`(KV·`S`)·`core/character.js`(작품 목록)·`images/pick.js`·`services/images.js`, 요약의 `S.settings.memCfg`·`plan()`·화면 표시(`flagMemo`). 서버로 옮기려면 이 의존을 인자(방·작품·설정)로 받게 먼저 다듬어야 합니다(3장 1번의 '남은 것'과 같은 일).
- **작품의 비공개 설정이 브라우저에서 빠집니다**: 지금은 `persona`·`secret`·`openings[].directive`·키워드북 `text`·명령어 `prompt`가 `index.html`에 그대로 실립니다(공개 저장소). 서버 조립이 되면 빌드가 작품을 '독자용'(제목·소개·출연진 desc·가이드·명령어 제목)과 '서버용'으로 갈라 내보내야 합니다 — 비공개(스포일러) 플래그(`hidden`)도 그때 진짜로 가려집니다(지금은 화면에서만 가림).
