# 사고 대응 절차 — 출시판 초안

> 「개인정보 보호법」 제34조와 시행령 제39조·39조의2·39조의3·40조(2026-09-11 시행본, 원문 확인)에 맞춘 절차예요. 개인정보 사고뿐 아니라 키 유출, 비용 폭주, 결제 사고, 금지 콘텐츠 사고도 같은 틀로 다뤄요.
> **시계는 '알게 된 때'부터 돌아요.** 72시간은 영업일이 아니라 실제 시간이에요.

## 1. 무엇이 '사고'인가
- 개인정보의 **유출·위조·변조·훼손·분실·도난**(이하 ‘유출등’), 또는 그 **가능성**이 있는 정황
- 비밀 값(키·비밀번호) 노출: 저장소에 올라감, 채팅·스크린샷에 보임, GitHub 비밀 검사 경고
- 비정상 비용: Anthropic·Supabase 사용량이 평소의 몇 배로 뜀
- 결제 사고: 중복 결제, 금액 오류, 위조된 결제 완료 신호
- 금지 콘텐츠 사고: 아동·청소년 성적 콘텐츠가 만들어지거나 공유된 정황, AI 제공사의 위반 통지
- 이용자 생명·안전 위기: 구체적인 자살 계획, 타인을 해치려는 계획

## 3. 처음 1시간 — 막고, 남기고, 적는다
1. **기록부를 연다**: 알게 된 시각, 알게 된 경로, 지금까지 아는 것. 이 시각이 72시간의 시작이에요
2. **증거를 남긴다**: 관련 로그(Supabase Auth·Edge Function·`admin_audit`), 화면을 캡처하거나 내보내 둬요. 고치기 전에 해요
3. **확산을 막는다**(해당하는 것만)
   - 노출된 키 폐기·재발급(Anthropic 콘솔, Edge Function Secrets 갱신)
   - 모든 세션 끊기: Supabase JWT 비밀 교체(모든 사용자 로그아웃) 또는 해당 계정 세션 종료
   - 기능 끄기: 대화 관문은 `chatUrl`을 비우거나 함수를 내림, 결제는 스토어를 '점검 중'으로, 공개 게시물은 숨김
   - 관리자 계정 탈취가 의심되면 `admins`에서 그 계정을 빼고(운영자 고정 계정이면 `owner_emails`도 확인), 비밀번호·2단계 인증을 다시 설정
4. **공지 여부를 정한다**: 서비스가 멈췄으면 공지사항에 '점검 중'을 먼저 올려요(원인은 확인된 것만)

## 4. 72시간 안 — 알리고 신고한다

### 이용자 통지(시행령 제39조) — **유출등이 된 모든 경우**
- **72시간 안에 서면등**(이메일, 서비스 안 알림 등)으로 알려요
- 예외: 확산 방지를 위한 긴급 조치(접속 경로 차단, 취약점 보완, 회수·삭제)가 필요하거나 천재지변 등 부득이한 경우 → 그 사유가 해소된 뒤 **즉시**
- 항목·경위를 아직 모르면: 유출된 사실, 지금까지 확인된 내용, 아래 문안의 3~6번을 **먼저** 알리고, 확인되는 대로 추가로 알려요
- 연락처를 모르는 이용자: 홈페이지(공지사항)에 **30일 이상** 게시해 대신해요

### 유출 '가능성' 통지(시행령 제39조의2·39조의3, 2026-09 신설)
- 개인정보처리시스템이나 운영 기기에 불법 접근이 있었고 유출이 의심되지만 **누구의 정보인지 특정하기 어려울 때**, 또는 일부 유출이 확인되어 다른 이용자의 정보도 유출되었을 수 있을 때
- 그때부터 72시간 안에, 가능성이 있는 **모든 이용자**에게: 가능성이 있는 항목, 의심 시점·경위, 이용자가 할 수 있는 일·운영자 조치·연락처, **확정되면 다시 알리겠다는 사실**

### 신고(시행령 제40조) — 다음 중 하나면 **72시간 안에** 개인정보보호위원회 또는 한국인터넷진흥원에
1. **1천 명 이상**의 정보가 유출등이 된 경우
2. 민감정보·고유식별정보가 유출등이 된 경우(HEART SYNC는 보통 처리하지 않음)
3. **외부의 불법 접근**(해킹)으로 유출등이 된 경우 — 숫자와 상관없이
- 내용을 다 모르면 먼저 신고하고 확인되는 대로 더해요
- 유출 경로를 확인해 회수·삭제하는 등으로 이용자 권익 침해 가능성이 현저히 낮아졌다면 신고하지 않을 수 있어요(그 판단 근거를 기록)

### 이용자 통지 문안(제34조① 1~6호를 모두 담음)
```
제목: [HEART SYNC] 개인정보 유출 사실을 알려 드립니다

HEART SYNC를 이용해 주시는 회원님께 진심으로 사과드립니다.
【날짜】에 회원님의 개인정보가 유출된 사실을 확인했습니다.

1. 유출된 항목: 【예) 이메일 주소, 닉네임】 (비밀번호·결제 정보는 포함되지 않았습니다 — 확인된 경우에만 적기)
2. 유출된 시점과 경위: 【예) 2026년 ○월 ○일 ○시경, 외부의 불법 접근으로】
3. 회원님이 하실 수 있는 일: 【예) 비밀번호 변경, 같은 비밀번호를 쓰는 다른 서비스의 비밀번호 변경, 출처를 알 수 없는 메일의 링크를 누르지 않기】
4. 저희가 한 조치와 피해 구제 절차: 【예) 접속 경로 차단, 취약점 보완, 관계 기관 신고. 피해가 생기면 아래로 알려 주시면 확인 후 구제해 드립니다】
5. 피해 신고·문의: heartsyncchat@gmail.com, 【전화】, 앱 MY → 고객센터
6. 회원님의 법적 권리: 「개인정보 보호법」 제39조에 따른 손해배상, 제39조의2에 따른 법정손해배상(300만 원 이하)을 청구하실 수 있고, 개인정보분쟁조정위원회(1833-6972, www.kopico.go.kr)에 분쟁조정을 신청하실 수 있습니다.

다시 한번 사과드리며, 재발하지 않도록 【재발 방지 대책 요약】하겠습니다.
【상호】 대표 【이름】
```

## 5. 유형별 플레이북

### A. DB·계정 정보 유출(`service_role` 키 노출, RLS 실수 등)
막기: 키 교체, 문제 정책 수정, 영향받은 표 확인 → 범위: `admin_audit`·Supabase 로그로 어떤 행이 읽혔는지 → 4장 통지·신고(외부 불법 접근이면 신고 대상)

### B. Anthropic 키 노출·비용 폭주
막기: 키 폐기·재발급, 콘솔 월 한도 확인, 대화 관문 일시 정지 → 범위: 사용량 그래프, `chat_usage`의 계정별 이상치 → 남용 계정 정지(운영정책). 대화 내용 유출이 아니면 개인정보 통지 대상은 아니지만 기록은 남겨요

### C. 관리자 계정 탈취
막기: 3장 3번 → 범위: 그 계정의 `admin_audit`(본 문의·내려받은 기록) → 문의 내용(이메일 등)이 열람되었으면 4장 통지, 외부 불법 접근이면 신고

### D. 결제 사고
막기: 스토어 점검 중, 웹훅 서명 검증 확인 → 범위: PortOne 거래 내역과 서버 장부 대조 → 잘못 결제된 금액은 공제 없이 환불(약관 제25조), 영향받은 회원에게 개별 안내

### E. 아동·청소년 성적 콘텐츠
막기: 해당 계정 정지, 공개된 것은 즉시 비공개 → 보존: 증거는 접근을 제한한 곳에 보존하고 **복제·전달하지 않음**(수사기관 제출 외) → 신고: 경찰청(182)·방송통신심의위원회(1377) → AI 제공사의 통지였다면 조치 결과를 회신 → 재발 방지: 어떤 표현이 자동 검사를 통과했는지 확인해 `safety.js` 판정을 보강

### F. 이용자 생명·안전 위기
대화에서 구체적인 계획이 보이고 급박하면, 이용자가 알려 준 정보로 112·119에 알릴 수 있어요(개인정보 보호법 제18조②3 — 생명·신체의 급박한 위험 🔎). 그 밖에는 안내 카드(109·1577-0199·1388)를 보여 주고, 문의로 연락이 오면 도움 기관을 안내해요. 운영자가 상담을 대신하지 않아요

### G. 서비스 장애
공지 → 실패한 턴은 자동 환원(약관 제25조) → 운영자 책임으로 4시간 이상 멈췄으면 PLUS 기간 연장(약관 제12조③) → 원인·조치 공지

## 6. 끝난 뒤
- 사고 보고서: 타임라인, 원인, 영향(사람 수·항목), 한 조치, 통지·신고 일시, 재발 방지 대책
- 이 문서와 내부 관리계획에서 고칠 것을 고쳐요
- 기록부와 보고서는 **3년** 보관해요(분쟁 대비)

## 7. 연습
연 1회, 'service_role 키가 저장소에 올라갔다'처럼 가정을 하나 정해 1~4장을 실제로 따라가 봐요(키 교체 순서, 통지 문안 채우기, 신고 사이트 위치 확인). 걸린 시간과 막힌 곳을 기록해요.
