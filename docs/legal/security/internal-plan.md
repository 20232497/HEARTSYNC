## 3. 교육
- 연 1회 이상 개인정보 보호 교육을 받아요(개인정보보호위원회 온라인 교육 등). 받은 날과 내용을 기록해요.
- 새 취급자는 일을 시작하기 전에, 이 계획과 운영정책의 '대화 열람' 원칙을 교육해요.

## 4. 접근 권한 관리
- 업무에 꼭 필요한 사람에게 꼭 필요한 권한만 줘요. 계정을 함께 쓰지 않아요.
- 관리자 권한은 Supabase `admins` 표와 각 콘솔의 멤버 목록으로 줘요. 부여·변경·말소할 때 일시·대상·이유를 기록하고 **3년** 보관해요 🔎.
- 취급자가 그만두거나 역할이 바뀌면 그날 안에 권한을 지우고, 함께 알던 비밀(관문 비밀번호 등)을 바꿔요.

## 5. 인증
- 개인정보처리시스템과 운영 메일함, 도메인·GitHub·Cloudflare 계정에는 **2단계 인증**을 켜요(인증 앱 또는 보안 키, 문자 인증은 되도록 쓰지 않음).
- 관리자 권한은 2단계 인증을 마친 세션(`aal2`)에서만 동작하게 해요(보안 점검 M1).
- 비밀번호는 비밀번호 관리자로 길고 무작위하게 만들고, 서비스마다 다르게 써요.

## 6. 접근 통제
- 데이터베이스는 RLS로 행 단위 접근을 막아요. 표를 새로 만들면 RLS를 켜고 정책을 검토한 뒤 배포해요(Security Advisor 확인).
- `service_role` 키, Anthropic 키, PortOne API·웹훅 비밀은 Edge Function Secrets에만 두고, 앱·저장소·메모·채팅에 붙여 넣지 않아요.
- 관리자 도구는 출시 배포에서 빼고 Cloudflare Access 뒤 또는 로컬에서만 열어요(M6).
- 일정 시간(30분) 쓰지 않으면 관리자 세션을 끝내요.

## 7. 암호화
- 모든 통신은 HTTPS, 운영 도메인에는 HSTS를 켜요.
- 비밀번호는 Supabase Auth가 해시로 저장해요. DB와 백업은 Supabase(AWS)가 저장 시 암호화해요.
- 개인정보를 파일로 내보내지 않는 것이 원칙이에요. 꼭 필요하면(수사기관 제출 등) 암호를 건 파일로 만들고, 쓴 뒤 바로 지우고 기록해요.

## 8. 접속 기록
- 관리자가 개인정보를 조회·수정·삭제·내려받기한 기록(누가, 언제, 무엇을, 어디서)을 `admin_audit` 표에 남겨요(M5). 관리자도 지울 수 없게 해요.
- 보관: **1년 이상**. 정보주체 5만 명 이상이 되거나 민감·고유식별정보를 처리하면 **2년 이상** 🔎.
- 점검: **월 1회** 기록을 훑어 평소와 다른 조회(대량 조회, 심야 조회, 내려받기)가 있는지 봐요. 내려받기가 있었으면 이유를 확인해 적어요 🔎.
- 이용자 요청의 접속 기록(통신비밀보호법)은 3개월 보관해요(L4).

## 9. 악성 프로그램 방지
- 운영 기기에 백신(Windows 보안)을 켜고, 운영체제·브라우저 자동 업데이트를 켜요.
- 브라우저 확장은 꼭 필요한 것만 둬요(관리 콘솔용 브라우저 프로필을 따로 쓰면 좋음).

## 10. 물리적 조치
- 운영 기기는 디스크 암호화(BitLocker·FileVault)와 짧은 화면 잠금을 켜요. 공용 PC에서는 관리 콘솔에 로그인하지 않아요.
- 기기를 잃어버리면 바로 모든 세션을 끊고(각 콘솔에서 로그아웃), 비밀번호와 키를 바꿔요.
- 보호자 요청 서류 등 종이 문서는 받지 않는 것이 원칙이에요. 받으면 잠금 보관하고 처리 후 파쇄해요.

## 11. 비밀 값 관리
| 비밀 | 보관 위치 | 바꾸는 때 |
|---|---|---|
| Anthropic API 키(회사) | Edge Function Secrets | 연 1회, 의심되면 즉시. 콘솔에서 월 지출 한도 설정 |
| Supabase `service_role`·JWT 비밀 | Supabase | 의심되면 즉시(모든 세션이 끊김) |
| PortOne API 비밀·웹훅 비밀 | Edge Function Secrets | 연 1회, 의심되면 즉시 |
| 소셜 로그인 Client Secret | Supabase 대시보드 | 연 1회 |
| 관리자 관문 비밀번호 | 비밀번호 관리자 | 취급자가 바뀔 때 |

GitHub 저장소의 비밀 검사(secret scanning)를 켜 두고, 경고가 오면 사고로 처리해요([incident-response.md](incident-response.md)).

## 12. 수탁자 관리
- 수탁자: Supabase, Anthropic, Cloudflare(국외), 【PortOne 운영사】, 【PG사】, 【본인인증 기관】(국내).
- 위탁 계약(약관·데이터 처리 부속서)에 처리 목적, 재위탁 제한, 안전성 확보, 사고 통지, 계약 종료 시 파기가 있는지 확인해 기록해요.
- 연 1회 각 회사의 보안 인증(SOC 2, ISO 27001 등)과 약관 변경을 확인해요. 바뀐 점이 있으면 처리방침을 고쳐요.

## 13. 파기
- 처리방침 3항의 보관 기간이 끝나면 자동으로 지우는 예약 작업(pg_cron)을 둬요: 이용량 1년, 접속 기록 3개월, 신고 기록 1·3년, 결제 기록 5년, 재가입 방지 해시 3년.
- 자동 파기가 아닌 파기(요청에 따른 삭제 등)는 일시·대상·방법을 기록해요.
