# HEART SYNC 상용화 계획

지금의 HEART SYNC는 **기능은 갖춘 프로토타입**입니다. 화면·서사 엔진·이미지·성인 모드 구조는 있지만, 돈을 받고 여러 사람이 쓰는 서비스가 되려면 "누가 쓰는지(로그인)", "어디에 저장하는지(서버)", "누가 AI 비용을 내는지(서버 키)", "돈이 어떻게 들어오는지(결제)"가 필요합니다.

## 0. 결론 먼저

- **로그인부터 시작하는 것이 맞습니다.** 계정이 있어야 결제·저장·성인 인증·신고를 모두 사람에 묶을 수 있습니다.
- 다만 **로그인만 따로 붙이면 쓸모가 없습니다.** 대화·하트가 여전히 브라우저에 있으면 기기를 바꾸면 사라지고, 하트는 브라우저 콘솔로 조작할 수 있습니다. 그래서 1단계는 **로그인 + 서버 저장**을 한 묶음으로, 2단계는 **서버가 AI를 대신 부르고 하트를 서버에서 차감**하는 것으로 잡았습니다.
- 추천 구성: **Supabase**(로그인·DB·파일 저장) + **Cloudflare Workers**(AI 호출 서버) + **Cloudflare Pages**(사이트) + **포트원**(결제·본인인증). 작은 팀이 가장 빨리, 월 고정비 몇만 원으로 시작할 수 있는 조합입니다.

## 1. 지금 상태에서 상용화를 막는 것

| 항목 | 지금 | 상용 서비스에서는 |
|---|---|---|
| AI 비용 | 사용자가 Anthropic·OpenRouter·Runware 키를 직접 넣음(BYOK) | 회사 키로 **서버가 대신 호출**. 사용자는 키를 몰라도 됨 |
| 하트·PLUS·결제 | 데모. 브라우저에서 숫자를 바꿀 수 있음 | **서버 원장**에서 차감·환불, 실제 PG 결제 |
| 저장 | 로그인하면 Supabase 계정에 저장해 기기끼리 이어짐, 로그인 안 하면 브라우저에만 | 하트·결제 등 돈과 관련된 값까지 **서버 기준**으로 |
| 로그인 | 이메일·카카오·네이버·Google(Supabase). 네이버는 검수 전이라 등록한 멤버만 | 네이버 검수, 약관 동의 절차 |
| 성인 확인 | 체크박스(자기 신고) — 휴대폰 본인인증은 시험 모드까지 구현, 기본 꺼짐(SETUP.md) | **본인인증(PASS·휴대폰)** 결과를 서버에 저장 |
| 커뮤니티 공개 | claude.ai 안에서만 동작 | 서버 DB, 검수·신고 |
| 사이트 호스팅 | GitHub Pages | GitHub Pages는 결제·SaaS가 주목적인 사이트를 허용하지 않음 → Cloudflare Pages 등으로 이전 |
| 법·약관 | 약관·개인정보처리방침 초안 공개(법률 검토 전), 사업자등록 전 | 사업자·법률 검토·청소년 보호 |
| 운영 | 고객센터(공지·FAQ·문의)와 관리자 도구 | 회원·결제 관리, 신고 처리, 비용·오류 모니터링 |

## 2. 전체 구성

```
[휴대폰·PC 브라우저]  HEART SYNC 앱 (Cloudflare Pages에서 배포)
      │
      ├─ 로그인 ─────────▶ Supabase Auth (카카오·구글, 세션 토큰)
      │
      ├─ 저장·불러오기 ──▶ Supabase DB (Postgres, 본인 데이터만 보이게 RLS) · Storage(그림)
      │
      └─ 대화·그림 요청 ─▶ API 서버 (Cloudflare Workers)
                              1) 로그인 토큰 확인
                              2) 턴 가격을 서버가 계산 → 무료 턴·하트 확인 후 차감 (DB 트랜잭션)
                              3) 프롬프트 조립(연기 규칙·안전 규칙은 서버가 붙임)
                              4) Anthropic / OpenRouter / Runware 호출 (회사 키)
                              5) 응답을 그대로 스트리밍 → 실패하면 환불 → 사용량 기록

[포트원] 결제·정기결제·본인인증 ──웹훅──▶ API 서버 ──▶ 하트 지급 / 구독 갱신 / 성인 인증 기록
```

**이 조합을 고른 이유**
- Supabase 하나로 로그인·DB·파일 저장이 해결되고, **카카오 로그인을 기본 지원**합니다. 무료로 시작해 Pro 월 $25.
- Cloudflare Workers는 AI 응답을 끊김 없이 스트리밍하기 좋고 월 $5부터. 지금 앱에 이미 있는 서버 연결 지점(`HEARTVERSE_CONFIG`의 `anthropicUrl`·`runwareUrl`·`openRouterUrl`·`serverKeys`)에 그대로 꽂을 수 있습니다.
- 대안: Firebase(카카오 로그인은 직접 연동 필요), 자체 서버(Node/NestJS — 규모가 커진 뒤).

## 3. 로그인 설계 (1순위)

> **지금 상태(2026-11)** — 로그인 화면에 카카오·네이버·Google 버튼이 있고(2026-11-03 Supabase에서 셋 다 켬 — Google은 11-03 프로덕션 게시로 누구나, 네이버는 검수 전이라 등록한 멤버만, 소셜 계정은 이메일 없이 가입), API 키는 계정에 평문으로 두지 않고 로그인 비밀번호로 기기에서 암호화한 `vault` 행에만 저장합니다(서버·관리자도 못 봄). 1단계의 앞부분을 넣었습니다. 이메일·비밀번호 로그인(Supabase Auth, REST 직접 호출)과 계정 저장(표 `public.kv` + RLS, 만드는 SQL은 [supabase.sql](supabase.sql))으로 PC·휴대폰의 대화·작품·설정·그림이 이어집니다. 카카오·구글은 Supabase 대시보드에서 켜면 로그인 화면에 버튼이 저절로 나타납니다. 하트·결제·AI 호출은 아직 브라우저 쪽(데모)이라, 하트 위조 방지는 2단계 그대로 남아 있습니다.

### 3-1. 로그인 수단

| 수단 | 시기 | 이유 |
|---|---|---|
| 카카오 | 1차 필수 | 국내 사용자 대부분이 가장 편하게 씀 |
| 구글 | 1차 | 카카오를 안 쓰는 사용자, PC 사용자 |
| 네이버 | 1차 | Supabase 기본 제공이 아니라 사용자 지정 OIDC 공급자(`custom:naver`)로 연동 — 버튼은 있음 |
| Apple | 앱스토어 출시 때 | iOS 앱에 다른 소셜 로그인이 있으면 함께 제공해야 함 |
| 이메일(로그인 링크) | 선택 | 소셜 계정을 쓰기 싫은 사용자 |

### 3-2. 화면 흐름

1. **첫 방문** — 로그인 없이 작품 둘러보기, 게스트 무료 체험(예: 3턴). 처음부터 로그인을 막으면 이탈이 큼
2. **로그인이 필요한 순간** — 체험 턴을 다 쓰거나, 대화 저장·결제·작품 만들기·커뮤니티 공개를 누를 때 로그인 시트
3. **로그인 화면** — 로고와 한 줄 소개, [카카오로 시작하기] [Google로 계속하기], 이메일 로그인 링크, 아래에 이용약관·개인정보처리방침
4. **첫 로그인 직후**
   - 약관 동의: 전체 동의 / 필수(이용약관 · 개인정보 수집·이용 · 만 14세 이상) / 선택(마케팅 수신)
   - 닉네임(크리에이터 이름)과 기본 페르소나
   - 이 기기에 게스트로 쓴 대화가 있으면 "대화 n개를 계정으로 옮길까요?"
5. **MY → 계정** — 로그인 수단, 성인 인증 상태, 구독·결제 수단, 로그아웃, 회원 탈퇴(삭제되는 데이터 안내)

### 3-3. 나이

- **가입은 만 14세 이상.** 14세 미만은 보호자 동의 절차가 필요해서, 받지 않는 쪽이 단순합니다
- **성인(19+) 콘텐츠는 로그인과 별도로 본인인증 1회.** 결과는 서버 프로필에 저장(`adult_verified_at`)하고, 서버가 그 값으로 성인 경로를 열고 닫습니다. 지금의 체크박스는 없앱니다

### 3-4. 지금 코드와 이어 붙이는 방법

- 저장소 `KV`는 이미 "브라우저 + 계정 db" 이중 저장 구조라, **서버 저장 어댑터**를 하나 더 붙이면 됩니다
- 설정 화면의 API 키 칸은 일반 사용자에게 숨기고 개발자 모드에서만 보이게
- `HEARTVERSE_CONFIG`에 API 서버 주소와 `serverKeys: true`를 넣어 BYOK를 끔

## 4. 데이터 구조 (DB)

| 테이블 | 주요 칸 | 설명 |
|---|---|---|
| `profiles` | id(로그인 계정), nickname, plan, plus_until, adult_verified_at, marketing_opt_in, created_at | 사용자 정보 |
| `heart_ledger` | user_id, delta(+/-), reason, ref_id, created_at | 하트 변동 기록. 잔액은 이 합계(또는 같은 트랜잭션에서 갱신하는 잔액 칸) |
| `free_turns` | user_id, day, used | 하루 무료 턴 |
| `payments` | user_id, provider, order_id, product, amount, status, created_at | 결제(웹훅으로 확정) |
| `subscriptions` | user_id, billing_key, status, current_period_end | PLUS 정기결제 |
| `characters` | id, owner_id, data(jsonb), visibility, adult_only, review_status | 내가 만든 작품 |
| `rooms` | id, user_id, character_id, doc(jsonb), updated_at | 대화방 — 처음엔 지금의 방 데이터를 통째로 저장해 옮기기 쉽게 |
| `images` | id, user_id, path, kind, rating, created_at | 그림(Storage에 비공개 저장) |
| `reports` | reporter_id, target_type, target_id, reason, status | 신고 |
| `usage_logs` | user_id, model, input_tokens, output_tokens, cost_usd, created_at | 원가 계산·이상 사용 감지 |

모든 테이블에 **RLS(본인 것만 읽고 쓰기)**를 켭니다. 하트·결제·성인 인증은 **서버만** 쓸 수 있게 합니다.

## 5. 서버(API)가 맡는 일

| API | 하는 일 |
|---|---|
| `POST /api/chat` | 턴 가격을 서버에서 계산(모델 × 출력량 × 기억력) → 무료 턴·하트 차감 → 프롬프트 조립(연기·안전 규칙을 서버가 붙여서 사용자가 바꿀 수 없게) → AI 응답 스트리밍 → 실패하면 환불 → 사용량 기록 |
| `POST /api/summary`, `/api/suggest` | 장기기억 요약·추천 답변. 무료지만 횟수 제한 |
| `POST /api/image` | 그림 하트 차감, 수위는 서버가 성인 인증 여부로 결정, 미성년 차단도 서버에서 한 번 더 |
| `POST /api/pay/webhook` | 포트원 결제 확인 → 하트 지급·구독 갱신 |
| 공통 | 사용자별 요청 제한, 금칙 필터, 오류·비용 기록 |

## 6. 결제

- **PG**: 포트원 V2 + 토스페이먼츠(카드·간편결제), 카카오페이·네이버페이
- **하트 팩**: 단건 결제 → 웹훅으로 확인된 뒤에만 지급
- **PLUS**: 정기결제(빌링키). 해지·환불, 다음 결제일 안내
- **법적 고지**: 사용한 디지털 재화는 청약철회가 제한된다는 안내(결제 전), 영수증, 화면 아래 사업자 정보
- 앱스토어로 낼 경우 인앱결제(수수료 15~30%)를 따로 붙여야 함

## 7. 원가와 가격 점검

가정: 1달러 = 1,400원, 한 턴에 입력 약 8천 토큰·출력 약 1천 토큰, 프롬프트 캐시 미적용. 실제 값은 `usage_logs`로 재야 합니다.

| 모델 | 한 턴 원가 | 지금 가격(보통 출력량) | 하트 1개 ₩19일 때 매출 | 하트 1개 ₩13일 때 매출 |
|---|---|---|---|---|
| 라이트 (Claude Haiku 5.5) | 약 ₩2 | ♥1 (하루 10턴 무료) | ₩19 | ₩13 |
| 스토리 (Claude Sonnet 5.5) | 약 ₩36 | ♥4 | ₩76 | ₩52 |
| 마스터 (Claude Opus 5.5) | 약 ₩73 | ♥8 | ₩152 | ₩104 |
| 성인 스토리 (Hermes 3 70B) | 약 ₩9 | ♥4 | ₩76 | ₩52 |
| 성인 마스터 (DeepSeek V3 — 2026-11 Magnum V4에서 바꿈) | 다시 재야 함(Magnum V4는 약 ₩35) | ♥8 | ₩152 | ₩104 |
| 그림 1장 (Runware) | 약 ₩4 | (가격 없음) | — | — |

- 하트 1개 값: 100개 ₩1,900이면 ₩19, 1,150개 ₩14,900이면 약 ₩13
- **주의**: PLUS는 스토리·마스터를 50% 할인해 줍니다. 큰 하트 팩으로 산 하트에 PLUS 할인까지 겹치면 스토리 한 턴 매출이 약 ₩26으로 원가(₩36)보다 낮아집니다. **PLUS 할인 폭을 조정하거나, 프롬프트 캐시로 원가를 낮춰야 합니다.** 캐시를 쓰면 반복되는 입력(설정·지난 대화)은 1/10 가격이라 원가가 크게 내려갑니다
- 결제 수수료(약 3%)와 부가세(10%)도 빼야 합니다
- 그림에도 하트 가격(예: 1장 ♥2)을 정해야 합니다
