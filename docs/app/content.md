## 순서 잠금

- **순서 잠금**(2026-11-11 프레임 4차 — 식별자 안정화, 사용자 결정 '어기면 빌드 실패'): 장소·컷씬·키워드북 그림은 목록의 순번이 곧 코드(MP<n>·EV<n>·lore-<n>)이고 방의 글([[MP2]])·수집 기록(S.shelf.seen)에 코드가 남으므로, 작품 폴더마다 **lock.json**(places 이름·cuts 제목·lore 첫 키는 자리로, openings id·cast code·episode.endings id는 이름표로 — tools/content-lock.mjs lockOf)에 공개된 것을 적고 빌드가 견줌. 판정은 **checkLock 한 곳**(빌드 buildContent와 잠금 명령이 같이 씀): 자리 목록은 맨 뒤에 더하기·이름 고치기는 통과, 중간에 끼우기·지우기·순서 바꾸기는 실패(어느 코드가 어디로 밀렸는지 안내) / 이름표 목록은 잠긴 id·code가 없어지면 실패(순서·더하기는 자유). **npm run content:lock** = 모든 작품의 잠금을 지금 내용으로 찍음(어긋난 작품이 있으면 아무것도 안 찍음), `-- --force <작품 id>`는 어긋난 채로 다시 찍음(바뀌는 자리를 표로 — 방이 끊길 수 있어 사용자 승인 필요). npm run build는 '아직 안 잠긴 것 n개'를 한 줄로 알리기만(경고 아님), **npm run check(CI)는 잠금이 최신이 아니면 실패**(2026-11-11 사용자 결정 — main에 들어간 것은 모두 잠긴 상태) → 작품을 고쳤으면 커밋 전에 content:lock. **check는 기준 가지(origin/main — 지금 가지가 갈라진 자리)의 잠금과도 견줌**(2026-11-12 프레임 5차 — content-lock.mjs readBaseLocks·checkBase, CI는 LOCK_BASE): lock.json을 지우거나 손으로 고쳐 다시 찍는 우회가 걸리고, 승인받은 강제 다시 찍기(--force)를 한 가지는 이 검사가 실패하는 것이 정상(병합 담당이 사용자 승인을 확인하고 병합 — docs/TEAM.md). git이 없으면 건너뛰고 알림. 한계: 맨 끝을 지우고 새로 더하면 이름 고치기와 구분 못 함, 키워드북 첫 키를 고치면 예전 방의 세계관 수첩에서 그 항목이 안 본 것으로 돌아감. 잠금 명령은 build.mjs를 동적으로 불러 씀(서로 import하므로 맨 윗단 await 금지). 작품 id(폴더 이름)는 잠그지 않음
