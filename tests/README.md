# tests/ — 시험

| 명령 | 무엇 | 걸리는 시간 |
|---|---|---|
| `npm test` | **단위 테스트** `tests/unit/*.test.mjs` — Node가 `src/js/` 모듈을 바로 import(브라우저 없음). 응답 파싱·키워드북·미성년 인물 막기·그림 태그 읽기와 감정 칸 낱말 점수·네트워크 시간 제한·서버에 남겨 둔 성인 인증 함수 | 1초 |
| `npm run e2e` | **흐름 시험** `tests/e2e/*.mjs` — Playwright(WebKit iPhone 13·SE, Chromium Galaxy)로 빌드된 `index.html`(사용자 사이트)과 `admin.html`(관리자 도구 — `admin`)을 정적 서버에 띄워 실제 화면 흐름을 돈다. 처음 한 번 `npx playwright install webkit chromium` | 4~5분 |
| `npm run e2e chatflow` | 흐름 시험 하나만(이름 여러 개 가능). `-- --retry`를 붙이면 실패한 시험만 한 번 더 돌림(CI가 씀) | |
| `npm run serve` | 저장소 루트를 정적 서버로만 띄움(휴대폰에서 같은 Wi-Fi로 열어 볼 때 등) | |

`page.evaluate: Execution context was destroyed, most likely because of a navigation`이 Chromium에서 드물게 나면 먼저 실제 이동인지 본다 — Playwright는 평가의 프로토콜 오류를 모두 이 문구로 바꾸는데, 이동 없이 `Promise was collected`인 경우가 있다(평가가 돌려준 약속이 끝나는 순간 GC가 돎. `DEBUG=pw:protocol`로 진짜 오류가 보임). 그때는 다시 돌리면 되고, 자주 나면 그 `evaluate(async …)`를 시작·기다리기·읽기로 나눈다.

`npm run e2e`는 `npm run build`가 만든 `index.html`·`admin.html`을 시험하므로 **빌드 뒤에** 돌린다(`admin.html`은 커밋하지 않아 새로 받은 사본에는 없음 — 없으면 `run.mjs`가 멈추고 빌드를 안내, CI도 `e2e.yml`에서 먼저 빌드 · `run.mjs`의 `PAGE`가 시험마다 어느 빌드를 여는지 정함). 스크린샷은 `tests/.shots/`(git에 안 들어감).

## CI(GitHub Actions)에서 도는 것
| 워크플로 | 언제 | 무엇 |
|---|---|---|
| **빌드 확인**(`.github/workflows/build.yml`) | PR마다 · main에 들어갈 때 | `npm ci` → `npm run check`(모듈·작품 검사, `index.html`이 소스와 같은지(`admin.html`은 커밋하지 않으니 만들어지는지와 git에 들어 있지 않은지), 순서 잠금이 최신인지, **기준 가지의 잠금과 맞는지**, 코드 정렬(`npm run format`)이 맞는지와 긴 줄이 예외 표 안인지, CLAUDE.md 상한과 지도 표의 경로 — `LOCK_BASE`로 PR이 들어갈 가지를 알려 줌) → `npm test` |
| **흐름 시험**(`.github/workflows/e2e.yml`) | PR마다 · 직접 실행 | `npm ci` → `npm run build`(커밋하지 않는 `admin.html`을 만듦) → 브라우저 두 종과 한글 글꼴 설치 → `npm run e2e -- --retry`(실패한 시험만 한 번 더 — 두 번 다 실패해야 실패, 다시 돌려 통과한 시험은 경고 줄로 남음). 실패하면 `tests/.shots`의 스크린샷을 `e2e-shots`로 올려 둠(7일). 시간대는 `Asia/Seoul` |

- **흐름 시험은 2026-11-26부터 필수 검사**예요(사용자 결정). 처음 두 주(11-12~11-26)는 '알림만'이었고, 그동안 CI 86번 중 다시 돌려 통과한 헛실패가 4번(cloud2 셋·social 하나 — 모두 --retry가 받아 냄), 실패 14번 중 12번은 11-22 하루 main 자체의 cloud2 시험 문제, 2번은 실제 문제였어요. 지정은 GitHub 저장소 설정이라 **사용자가 직접** 해요: 저장소 → Settings → Branches(또는 Rules → Rulesets) → `main` 규칙 → *Require status checks to pass* → 검사 이름 `e2e`(흐름 시험)와 `check`(빌드 확인)를 고름.
- 흐름 시험의 실행 환경은 `ubuntu-24.04`로 고정해 뒀어요 — `ubuntu-latest`(26.04)에는 지금 Playwright(1.56.1)가 WebKit을 깔지 못해요. Playwright를 올릴 때 워크플로의 `runs-on`도 그 판이 지원하는 ubuntu로 같이 올려요. 빌드 확인은 node와 git만 써서 `ubuntu-latest` 그대로예요.
- 이 PC와 CI의 차이: CI는 리눅스(ubuntu)·`HS_ADMIN_PW` 없음(`gate`의 맞는 비밀번호 입력은 건너뜀). CI에서만 깨지는 시험이 나오면 시험을 느슨하게 고치지 말고 CI 환경 값을 맞춰요(시간대·글꼴 — 워크플로의 `env`).

## 흐름 시험(e2e)
- 모든 스크립트는 Supabase·카카오 로그인을 `page.route`로 흉내 내므로 실제 서버·계정은 건드리지 않고, 키·이메일은 모두 시험용 가짜 값이다. 계정을 흉내 내지 않는 시험도 `_offline.mjs`의 `noSupabase()`로 Supabase 요청을 빈 목록으로 받는다(로그인하지 않아도 MY가 공지사항을 확인하므로).
- 스크립트는 결과를 JSON으로 찍기만 하고 늘 exit 0으로 끝난다. `tests/run.mjs`가 결과의 `fail`·`error`·`errors`·`errs`·`pageerror` 칸이 비었는지로 판정한다(WebKit이 뷰포트 메타의 `interactive-widget`을 모른다고 남기는 콘솔 알림 하나는 셈에서 뺌 — 안드로이드 크롬용 값, 화면에는 없음). 새 시험을 더할 땐 같은 모양으로 쓰고(`console.log(JSON.stringify(res))`, 오류는 위 칸 이름에), `run.mjs`의 `SUITES`에 한 줄 설명을 더한다.
- 인자: `node tests/e2e/<이름>.mjs <URL> [스크린샷 폴더]` (`mobile.mjs`는 URL 여러 개 + `SHOT_DIR` 환경변수).

| 스크립트 | 보는 것 |
|---|---|
| `gate.mjs` | 관리자 비밀번호 관문: 가짜 https 호스트(`heartsync.test` — 저장소 파일을 그대로 줌, 실제 네트워크 없음)에서 관문이 서고 레일이 숨음, 틀린 비밀번호는 거부, 기억(`hv1_admin`)이 있으면 바로 부팅, 사용자 사이트에는 관문이 없음. 맞는 비밀번호 입력은 환경변수 `HS_ADMIN_PW`가 있을 때만(저장소에 비밀번호를 적지 않으려고) |
| `admin.mjs` | 관리자 도구(admin.html, Desktop Chrome·iPhone 13): 메뉴 다섯(홈·대화·공지·스토어·MY)과 공지·고객센터 화면·작품 상세가 그려지는지, 출시판 제외(`hold`)를 켠 작품이 상세에 '출시판 제외 — 까닭'·홈 카드에 '출시판 제외'로 보이는지, 관문·고객센터 관리 함수가 있고 로컬 주소에서는 관문이 서지 않는지. 이어서 **사용자 빌드**(index.html)를 열어 메뉴가 같고 관리자 함수(`gate`·`gateNeeded`·`lockAdmin`·`noticeSheet`·`loadInbox`)가 없으며 MY의 `#meExt` 자리가 비었는지 |
| `social.mjs` | 로그인 화면의 카카오·네이버·Google 버튼(아이폰 SE 폭), 안 켠 공급자 안내, PC 게스트 대화·페르소나 사진 → 이메일 없는 카카오 가입(계정이 비어 전부 올라감, 올리지 않는 칸은 없음), 휴대폰 게스트 대화 → 로그인 → 합치기, PC가 받으면 휴대폰 페르소나 사진도 보임, API 키는 어디에도 안 올라감, 취소 오류 안내. 대화·찜 없이 직접 만든 페르소나만 있는 기기도 로그인하면 합치기를 묻고('페르소나 1개'), 합치면 이 기기와 계정에 남음 |
| `cloud2.mjs` | 계정 저장: PC 게스트 → 이메일 가입(이 기기 데이터를 올림) → 휴대폰 로그인으로 대화·그림 받음 → 휴대폰 새 대화를 PC가 받음 → 내 서재(찜)의 날짜 관문: 날짜 전에는 계정에 안 올라가고, 날짜 뒤에는 두 기기의 찜이 합쳐지며 찜을 푼 것도 전해짐(시험이 `SHELF.syncFrom`을 바꿔 양쪽을 봄 — 페이지를 열자마자 '날짜 전'으로 잡아 두어, 실제 날짜가 그 상수(2026-11-23)를 지난 뒤에도 같게 돎) → API 키는 계정에 안 올라감(서버 표 제약 `kv_no_plain_keys`) → 휴대폰 로그아웃(기기 지우기) → 갤럭시 게스트 대화 합치기 → 계정 삭제 → **로그아웃 보호**: 저장 요청만 느리게·실패하게 한 채(가짜 서버가 첫 저장 요청을 붙잡아 둔 채로 누름 — 시간에 기대지 않음) '기기 데이터도 지우기'로 로그아웃하면 기다리는 동안 가림막이 화면을 덮고 키 눌림도 막으며 아무것도 지우지 않고, 붙잡은 요청이 실패로 끝나면 '아직 올리지 못한 것이 있어요' 창 — 실패하는 동안 '다시 올리기'를 눌러도 그대로, 서버가 돌아온 뒤 '다시 올리기'로 올라간 다음에야 지움 / 다른 기기: 실패하는 채로 '지금 동기화'가 못 했다고 알리고, '지우지 않고 로그아웃'은 로그아웃만 하고 대화를 남김 / **건너뛴 행 다시 받기**: PC가 방을 열어 둔 사이 휴대폰이 그 방을 고침 → PC의 받기는 덮지 않고 넘어감 → 방에서 나오면 그 방만 다시 받고 메모리의 옛 사본을 놓으며, 다시 열면 받은 내용으로 열림. 응답 생성·요약이 쓰고 있는 방은 화면을 떠났어도 미뤘다가 그 일이 끝난 뒤에 받음 / **전송은 한 번에 하나**: 앞의 저장 요청이 붙잡힌 동안 같은 키를 또 바꿔도 겹쳐 나가지 않고 계정에 마지막 값이 남음 / **합치기 창을 Esc로** 닫아도 합치고 로그인 뒤 처리가 끝남 / **'계정 것만 쓰기'**: 계정에 대화 목록 행이 없으면 이 기기의 목록을 비우고 본문은 남김 / **기기 지우기 실패**: 큰 저장소를 비우지 못하면 지웠다고 하지 않고 알림 / **두 기기의 방 목록 합치기**: 두 기기가 각각 새 방을 만들고, 한쪽은 새 방이 든 목록을 못 올린 채로(올리기를 잠깐 막음) 다른 쪽 목록을 받음 → 한 바퀴 주고받으면 양쪽 목록과 계정 목록에 둘 다 남고, 다 맞춰진 뒤에는 더 올리지 않음. 합친 결과가 계정 목록과 같아도 이 기기의 옛 목록이 대기열에 있으면 합친 것으로 바꿔 올림 / **삭제 표식**: 한쪽에서 지운 방이 다른 쪽에서도 사라지고(목록·본문), 그쪽이 표식을 받기 전에 시작한 저장(본문 쓰기를 붙잡아 두어 표식을 처리할 때까지 끝나지 않게 함)과 받은 뒤의 늦은 저장 어느 것으로도 되살아나지 않으며 계정에는 표식이 남음. MY '모든 데이터 초기화': 첫 지우기(방이 아닌 행)를 서버가 거절하면(4xx) 멈춰 알리고 계정에 다시 올리지 않음(더 새 값이 그대로), 적용됐는데 답만 잃으면(5xx) 방이 아닌 행만 다시 올림(방 행의 더 새 값은 그대로). 계정 쪽 지우기가 중간에 실패하면(방이 아닌 행은 지워지고 방의 표식 쓰기가 실패) 새로고침·기기 지우기 없이 멈춰 알리고 방은 그대로·지워진 행은 이 기기의 것으로 다시 올라감, 다시 시도하면 계정의 방 행은 삭제 표식으로·나머지 행은 지워지고 새로고침 — 그 방을 받아 둔 다른 기기가 받으면 방이 사라지고 다시 올려도 되살아나지 않음, 덜 지워진 계정(half)에는 '전부 지움' 표식이 없어 휴대폰이 그사이 받아도 지워지지 않음, 다시 시도에서 표식 올리기가 한 번 실패해도 한 번 더 해 봐서 계정에 표식(`wipe`)이 남고 휴대폰은 다음 받기에서 자기 페르소나·하트까지 지운 뒤 새로고침해 알림(계정에 되살려 올리지 않음), 지운 PC와 따른 휴대폰은 계정의 행을 전부 다시 받아(표식이 응답에 들어옴) 같은 표식을 다시 받아도 새로고침하지 않음, 그 뒤 처음 로그인하는 기기는 표식을 따르지 않음(게스트로 만든 페르소나가 남음) |
