# content/ — 작품(세계관·캐릭터) 폴더

HEART SYNC 오리지널 작품은 **작품 하나 = 폴더 하나**예요. 빌드(`npm run build`)가 이 폴더를 모두 찾아 검사한 뒤 `index.html`의 `ORIGINALS`·`HOME_ROWS`로 넣어요. 목록 파일은 없어요 — 폴더를 더하면 그대로 나란히 등록돼요. 작품 폴더의 `images/`에 앱 밖에서 만든 그림을 이름 규칙대로 넣으면 빌드가 함께 실어요(아래 '그림 싣기').

## 맨 위 폴더 = 관심있는 대화(aud)

| 폴더 | aud | 뜻 | 홈에 보이는 때 |
|---|---|---|---|
| `f/` | `f` | **여성향** — 남성 캐릭터와의 대화 | '여성향'·'전체'를 골랐을 때 |
| `m/` | `m` | **남성향** — 여성 캐릭터와의 대화 | '남성향'·'전체'를 골랐을 때 |
| `all/` | `all` | 전체 — 남녀가 섞인 작품 | '전체'를 골랐을 때만 |

작품의 `aud`는 **폴더가 정해요**. `work.js`에 `aud`를 쓰지 않아요(쓰면 폴더와 같아야 하고, 다르면 빌드 실패). 남성향 작품을 여성향으로 옮기려면 폴더를 `m/`에서 `f/`로 옮기면 끝이에요.

## 그 아래 = 작품 폴더 또는 홈 가로 줄 폴더

```
content/
├─ f/                         여성향
│  ├─ fate/                   홈 가로 줄 「다섯 남자, 하나의 비밀」 (_row.json이 있으면 줄 폴더)
│  │  ├─ _row.json            줄 제목·부제·순서
│  │  ├─ hwanghu/             계약 황후의 백 일
│  │  │  ├─ work.js
│  │  │  └─ images/           그림(선택): KAS0.webp(인물 코드+감정 번호) · MP1.webp(장소) · EV1.webp(컷씬) · cover.webp · lore-1.webp …
│  │  ├─ hasuk/work.js        서촌 오월 하숙집
│  │  ├─ lethe/work.js        호텔 레테: 마흔아홉 번째 밤
│  │  └─ geumseo/work.js      금서고의 사서 — 책 하나 = 장소 하나, 인물마다 '먹빛 모습' 폼
│  ├─ seodoyun/work.js        흑우 탐정사무소 (줄 없는 단독 작품)
│  ├─ kael/work.js
│  └─ baekyeon/work.js
├─ m/                         남성향
│  ├─ survive/                홈 가로 줄 「살아남는 자가 역사를 쓴다」
│  │  ├─ _row.json
│  │  ├─ daeyeon/  baekya/  sipjeol/
│  ├─ godseats/work.js        신님들, 관전 매너 좀
│  ├─ yunhaera/work.js
│  └─ hangyeoul/work.js
└─ all/                       전체(남녀 혼성)
   └─ minwon/work.js          야간 민원실 B1 — places·cuts·commands·hidden·폼(of)을 모두 쓰는 예시
```

- **작품 폴더**: `work.js`가 든 폴더. 폴더 이름 = 작품 `id`(영문 소문자·숫자·`-`·`_`).
- **줄 폴더**: `_row.json`이 든 폴더. 안에 작품 폴더를 두면 그 작품들이 홈의 가로 줄 하나로 모여요. 폴더 이름이 곧 작품의 `row` 값이라 `work.js`에 `row`를 쓰지 않아요. 줄 이름은 `f`·`m`·`all` 전체에서 하나만.
- `_`·`.`로 시작하는 폴더·파일은 빌드가 건너뛰어요(초안을 잠시 빼 둘 때 `_draft/`처럼).

## 새 세계관 추가 — 폴더 하나 복사

1. 가장 비슷한 작품 폴더를 복사해요.
   - 여성향 남주 군상극을 「다섯 남자, 하나의 비밀」 줄에 → `f/fate/hwanghu/`를 `f/fate/새id/`로
   - 남성향 히로인 군상극을 「살아남는 자가 역사를 쓴다」 줄에 → `m/survive/daeyeon/`을 `m/survive/새id/`로
   - 1:1 캐릭터 → `f/seodoyun/`(남자 캐릭터) 또는 `m/yunhaera/`(여자 캐릭터)
   - 새 홈 가로 줄을 만들려면 `f/새줄/_row.json`을 만들고 그 안에 작품 폴더를 둬요.
2. `work.js`에서 `id`를 폴더 이름과 같게 바꾸고 내용을 고쳐요.
3. `export const order = 숫자`로 순서를 정해요(작을수록 홈 대표 작품·오리지널 목록에서 앞). 같은 줄 안의 순서도 이 숫자를 따라요. 빼면 맨 뒤.
4. `npm run build`(또는 `npm run dev`를 켜 두면 저장할 때마다 자동). 틀린 곳이 있으면 `content/f/fate/새id: …`처럼 어디가 왜 틀렸는지 알려 줘요.
5. `npm run content:report` — 작품마다 뼈대 칸(키워드북·시작 상황·장소·컷씬·명령어·가이드·첫 답변 추천·배경 장소·그림)이 얼마나 찼는지 표로 보여 주고, 기준보다 얕은 칸에 ▽를 붙여요(검사가 아니라 안내 — 빌드는 통과해도 얕은 칸은 여기서 보임).
6. `npm run content:lock` — 새로 더한 장소·컷씬·키워드북·시작 상황·인물을 **순서 잠금**에 찍어요(아래 '순서 잠금'). 작품 폴더에 `lock.json`이 생기거나 바뀌어요.
7. `index.html`·`admin.html`과 `lock.json`도 같이 커밋해요(GitHub Actions의 `npm run check`가 결과물이 소스와 같은지, 잠금이 최신인지 확인).

## 순서 잠금 — 공개된 번호는 바뀌지 않게

장소·컷씬·키워드북 그림은 **목록의 순번이 곧 코드**예요(`MP2` = `places`의 둘째, `EV1` = `cuts`의 첫째, `lore-3` = 키워드북 셋째 항목의 그림). 이미 만든 대화방의 글에는 `[[MP2]]` 같은 태그가, 도감의 '모은 그림' 기록에는 코드가 남아 있어서, 목록 **중간에 끼우거나 지우거나 순서를 바꾸면** 그 대화방과 기록이 엉뚱한 장소·컷씬을 가리키게 돼요. 시작 상황의 `id`와 인물 `code`도 없어지면 대화방이 끊겨요.

그래서 작품 폴더마다 `lock.json`(빌드가 지키는 잠금 — 손으로 고치지 않아요)에 공개된 것을 적어 두고, 빌드가 지금 내용과 견줘요.

| 목록 | 잠그는 것 | 해도 되는 것 | 빌드가 멈추는 것 |
|---|---|---|---|
| `places`·`cuts`·`lore` | 자리(순번)마다의 이름 — 장소 이름·컷씬 제목·키워드북의 첫 키 | **맨 뒤에 더하기**, 이름·설명·태그 고치기 | 중간에 끼우기, 지우기, 순서 바꾸기 |
| `openings`·`cast` | 시작 상황 `id`·인물 `code` | 새로 더하기, 순서 바꾸기, 제목·이름·글 고치기 | `id`·`code`를 없애거나 바꾸기 |

- **작품을 고친 뒤 커밋 전에 `npm run content:lock`을 한 번** 돌려요 — 뒤에 더한 항목과 고친 이름을 잠금에 찍어요. `npm run build`는 아직 안 잠긴 것이 있으면 한 줄로 알리기만 하지만, 병합 전 검사(`npm run check`·GitHub Actions)는 잠금이 최신이 아니면 실패해요(main에 들어간 것은 늘 모두 잠긴 상태).
- 어긋나면 빌드가 어느 코드가 어디로 밀렸는지 알려 줘요(예: `MP2 '서고'이(가) MP3 자리로 밀렸어요`). **새 항목은 맨 뒤에** 더하면 돼요. 쓰지 않게 된 장소·컷씬은 지우지 말고 그대로 두세요(그 번호를 본 대화방이 있을 수 있어요).
- 정말 순서를 바꾸거나 지워야 하면 `npm run content:lock -- --force <작품 id>` — 바뀌는 자리를 표로 보여 준 뒤 그 작품의 잠금을 다시 찍어요. 이미 만든 대화방과 수집 기록이 끊길 수 있어 **사용자 승인이 있을 때만** 써요(docs/TEAM.md).
- 이름으로 가리기 때문에 한 작품 안에서 장소 이름·컷씬 제목·키워드북의 첫 키는 겹치면 안 돼요(빌드 검사).
- 한계: 맨 끝 항목을 지우고 새 항목을 더하면 '이름 고치기'와 구분하지 못해 통과해요. 키워드북의 첫 키를 고치면(잠금은 허용) 예전 대화방의 세계관 수첩에서 그 항목이 '아직 안 본 것'으로 돌아가요 — 첫 키는 되도록 그대로 두고 뒤에 키를 더하세요.
- 판정 규칙은 `tools/content-lock.mjs`의 `checkLock` 한 곳이에요(빌드와 잠금 명령이 같이 씀).

## work.js 모양

```js
/* 한 줄 설명 */
export const order = 40; // 홈·오리지널 목록 순서(작을수록 앞)

export default {
  id: "newworld", name: "작품 이름", title: "작품 제목", glyph: "字", cat: "로맨스", pal: 1, motif: "petals", world_mode: true, isNew: true,
  oneLiner: "카드에 보이는 한 줄 소개",
  artTags: "dark fantasy, ruined cathedral, candlelight, …",   // 세계관 영문 낱말(앱 밖에서 그림을 만들 때)
  tags: ["태그", "…"],
  desc: "상세 페이지 소개",
  guide: "플레이 가이드 — 독자에게 주는 안내문(선택, 줄바꿈만, 1,000자 이내)",
  noteTemplate: "## 시작 설정\n- 관계: \n- 상황: ",   // 유저노트 양식(선택) — 대화방 유저노트의 '이 작품의 양식 넣기'가 넣는 글
  recommend: "master",   // 권장 모델(선택) — lite·story·master. 새 대화방이 이 모델로 시작(빼면 앱 기본 추천인 story)
  creator: "제작자 이름", exclusive: true, publishedAt: "2026-11-09",   // 작품 메타(선택) — 빼면 HEART SYNC 스튜디오 · 독점 아님 · 공개일 없음
  persona: `AI에게 주는 인물·진상 설정 …`,
  world: `세계관 규칙 …`,
  speech: `문체·말투 예시 …`,
  secret: "숨은 설정",
  fields: ["📅 날짜", "📍 장소", "❤️ 호감도"], gauge: "❤️ 호감도",

          { keys: ["제국"], text: "늘 적용되는 전제", always: true, kind: "concept", tags: "…" },   // 상시 항목(선택)
          { keys: ["열쇠"], also: ["지하", "창고"], not: ["꿈"], order: 5, text: "…", kind: "item", tags: "…" } ],   // 보조 키·제외 낱말·우선순위(선택)
  cast: [ { code: "KAS", name: "카시안", desc: "독자에게 보이는 소개(비밀은 persona에만)", look: "29세 남성, 흑발, …", tags: "black hair, golden eyes, black military uniform, …", hidden: [13] },   // hidden(선택): 비공개(스포일러) 감정 번호
          { code: "KASD", name: "카시안(용의 모습)", of: "KAS", look: "…", tags: "…" } ],   // 다른 모습(폼)은 별도 코드 — 선택
  places: [ { name: "루벨리아 황궁 알현실", desc: "…", tags: "throne room, gothic, …" }, { name: "지하 봉인실", hidden: true } ],   // 장소 → MP1, MP2… — 선택. hidden: true면 그림을 대화에 나올 때까지 가림
  cuts: [ { title: "첫 입맞춤", when: "카시안이 처음으로 먼저 입을 맞추는 순간", tags: "…" } ],   // 컷씬 → EV1, EV2… — 선택
  commands: [ { cmd: "알현", title: "황제 알현", desc: "독자용 설명", prompt: "AI에게 주는 지시 — 장면을 알현실로 옮기고 …" },   // 대화방 !알현 — 선택

               place: 1, suggestions: ["먼저 인사를 건넨다", "말없이 지켜본다", "이름을 묻는다"], lead: { text: "처음 몇 턴은 …", turns: 3 } } ]   // place·suggestions·lead는 선택

```

| 칸 | 뜻 |
|---|---|
| `cat` | 로맨스·판타지·RPG·미스터리·일상·시뮬레이션 중 하나 |
| `pal`·`motif`·`glyph` | 표지 색(0~7)·무늬(rain·city·stars·glow·petals·ash·curtain)·가운데 한 글자 |
| `world_mode` | 여러 인물이 나오는 군상극(세계관). 1:1 캐릭터면 빼요 |
| `creator`·`exclusive`·`publishedAt` | 작품 메타(선택). `creator`는 제작자 이름(빼면 `HEART SYNC 스튜디오` — `src/js/core/constants.js` DEFAULT_CREATOR), `exclusive: true`는 독점 작품('독점' 배지), `publishedAt`은 공개일 `"YYYY-MM-DD"`. 상세 페이지 머리와 도감 작품 칸에 보여요(홈 카드에는 안 보임). 지금은 표시만 하고, 제작자 보상·독점 가산은 서버 원장이 생긴 뒤의 일이에요(`docs/ROADMAP.md` 5장) |
| `noteTemplate` | 유저노트 양식(선택) — 대화방 메뉴 → 유저노트의 '이 작품의 양식 넣기' 버튼이 넣는 글(유저노트 한도 2,000자 이내, 줄바꿈은 `\n`). 이 칸이 있는 작품에서만 버튼이 떠요. 독자가 채울 빈칸이 있는 양식을 적어요(예: `m/godseats`의 커스텀 모드 양식 — 시작 상황의 `directive`가 유저노트를 읽게 해 둠) |
| `recommend` | 권장 모델(선택) — `lite`·`story`·`master` 중 하나(`src/js/ai/models.js` MODELS의 키), 빼면 `story`. **새 대화방이 이 모델로 시작**하고, 모델 선택 시트에서 그 모델에 '권장' 배지가 붙어요. 빼면 앱의 기본 추천 모델(스토리 — '추천' 표시)로 시작하고 '권장' 배지는 없어요. 무료 턴으로 가볍게 시작하게 하려면 `lite`를 적어요(스토리·마스터는 첫 턴부터 하트를 써요) |
| `guide` | 플레이 가이드(선택) — 제작자가 **독자에게** 주는 안내문(어떻게 시작하면 좋은지·쓸 만한 명령어·주의할 점). 마크다운 없이 줄바꿈만, 1,000자 이내(`src/js/core/constants.js` LIMITS.guide). 상세 페이지 소개 아래·도감 작품 칸·대화방 메뉴의 '플레이 가이드'에 보이고 AI에는 보내지 않아요(AI 지시는 `persona`·`world`에). 예: `m/godseats` |
| `fields`·`gauge` | 상태창 칸 이름(3글자 안팎)과 관계 게이지 칸. 시작 상황 `status`의 칸은 `fields`에 있어야 해요 |
| `cast` | 출연진. `code`는 **인물 코드 — 영문 대문자 1~4자**(한서윤 → `HSY`, 카시안 → `KAS`; 숫자는 안 되고 `MP`·`EV`는 예약). 그림 코드는 인물 코드 바로 뒤에 감정·행동 번호를 붙인 한 토큰이에요: 본문 태그 `[[HSY3]]`, 그림 파일 `HSY3.webp`(번호는 기본 감정 0~14 — `src/js/core/constants.js`의 `SIT`, 아래 '그림 코드 체계'). `of`(선택)는 다른 모습(폼)일 때 본체 인물의 코드 — 폼은 별도 코드로 그림을 갖고 AI는 '그 모습일 때만' 그 코드를 써요. `desc`(선택)는 상세 페이지 인물 시트(도감)에 보이는 독자용 소개 — 비밀·진상은 `persona`에만 적어요. `look`은 한국어 외모(AI가 읽고, 성별로 작품의 aud를 짐작). `tags`(선택)는 그 인물의 외모를 영문 Danbooru 태그로 적은 글 — 앱은 쓰지 않고, **앱 밖에서 그림을 만들 때** 같은 인물을 매번 같은 생김새로 맞추는 기준이에요(한국어는 넣지 않기 — 빌드가 막음). 그림을 위한 메모: 옷·머리만 적으면 인물끼리 얼굴이 같아지니 눈매(`narrow eyes`·`droopy eyes`·`round eyes` 등)·눈썹·앞머리(`parted bangs`·`side-swept bangs`·`forehead`)·점·주근깨도 적고, `big eyes`처럼 어려 보이는 낱말과 손에 든 물건(`holding …`)은 넣지 않기. 무기는 검 길이 이하를 기본으로(긴 막대 끝에 날이 달린 무기는 세로 그림에서 잘려요). 색이나 옷이 번지는 낱말도 조심하기 — `red hair ribbon`은 머리칼을 붉게, `white dress shirt`는 치마를, `mourning dress`는 서양 드레스를, `police`는 현대 경찰복을 불러요. `hidden`(선택)은 **비공개(스포일러) 감정 번호 배열**(예: `[13]` — 1~14, 0 프로필은 안 됨) — 그 칸 그림은 도감·상세의 미리보기에서 🔒 카드로 가리고, 대화에 그 코드가 실제로 나온 방(본문·갤러리)에서만 보여요. **화면에서만 가리는 장치예요**(2026-11-09 결정) — 그림 파일과 장소·컷씬 이름은 배포물(`index.html`·`content/`)에 그대로 실려 주소를 직접 열면 볼 수 있으니, 보통 독자의 스포일러 방지용으로 써요. 완전한 비공개는 서버가 프롬프트를 조립하게 된 뒤(`docs/ROADMAP.md` 6장). 1:1 캐릭터도 `cast` 한 명을 적어요(`f/kael` → `KAEL`). 빼면 앱이 설정의 `외모:` 줄로 한 명(코드 `C`)을 만들고 그때는 맨 위 `lookTags`가 `tags` 자리 |
| `places` | 장소 목록(선택) `[{ name, desc, tags }]`. 순서가 곧 코드 — 첫 항목이 `MP1`, 둘째가 `MP2`…(그래서 새 장소는 **맨 뒤에** — '순서 잠금'). AI는 장면의 장소가 바뀔 때 본문 첫 줄에 `[[MP1]]`을 넣고, 대화방의 `!지도` 명령어가 목록을 보여 줘요. 그림은 `images/MP1.webp`. `tags`는 그 장소를 그릴 영문 낱말(앱 밖에서). `hidden: true`(선택)면 비공개 — 도감·상세·`!지도`에서 **그림만** 🔒로 가리고(이름·설명은 보여요 — 무엇을 모으는지는 알 수 있게), 대화에서 `[[MP<n>]]`을 한 번 본 뒤에는 도감·상세에서도 그림이 보여요(AI에게 주는 목록에는 그대로 들어가요) |
| `cuts` | 컷씬 목록(선택) `[{ title, when, tags }]`. 순서가 곧 코드 — `EV1`, `EV2`…(새 컷씬은 **맨 뒤에** — '순서 잠금'). `when`(나오는 조건)이 처음 이루어지는 순간 AI가 `[[EV1]]`을 한 번 넣어요. 그림은 `images/EV1.webp`. `hidden: true`(선택)면 도감·상세에서 **그림만** 🔒로 가려요(제목·조건은 보이니, 제목 자체가 스포일러면 에둘러 적기 — 대화에 나오면 그 방의 갤러리에, 그 뒤로는 도감·상세에서도 보여요) |
| `commands` | 작품 명령어(선택) `[{ cmd, title, desc, prompt 또는 text }]`. 상세 페이지 '명령어' 카드에 보이고, 대화방 입력창에 `!cmd`를 치면 **`prompt`가 있는 명령어('이야기')**는 말풍선은 그대로 두고 AI에 `prompt`가 `//` 연출 지시로 가요(한 턴을 써요 — 예: `m/godseats`의 `!퀘스트`·`!관람석`·`!쉼터`). **`text`가 있는 명령어('즉답')**는 AI를 부르지 않고 그 글을 바로 답으로 보여 줘요(하트·턴을 쓰지 않음, 1,000자 이내, `[[코드번호]]` 그림 태그 가능 — 규칙 안내·용어집·인물 관계처럼 늘 같은 글에). 둘 중 하나만 적어요. 앱 명령어의 이름·별칭(`상태창`·`상태`·`갤러리`·`도감`·`지도`·`장소`·`도움말`·`명령어`·`help`·`시간경과`·`새사건`·`조연등장`·`반복금지` — `src/js/core/commands.js` APP_COMMANDS)은 쓸 수 없어요(빌드 검사) |
| `lore` | 키워드북 `[{ keys, text, kind, tags, always, order, not, also }]`. 대화(최근 메시지 3개)에 `keys`가 나오면 `text`를 AI에 전달해요. **고르는 규칙**(`src/js/ai/prompt/lore.js` matchLore 한 곳): `always: true`는 **상시 항목** — 키워드와 상관없이 매 턴 들어가요(그 세계에서 늘 사실인 전제에만, 꼭 필요한 것 하나둘). `also: [낱말…]`은 **보조 키** — `keys` 중 하나와 `also` 중 하나가 함께 나와야 들어가요(흔한 낱말이 엉뚱한 장면에서 걸리는 것을 막음). `not: [낱말…]`은 **제외 낱말** — 이 낱말이 나오면 넣지 않아요. `order`(숫자, 기본 0)는 **우선순위** — 클수록 먼저 담겨요. 한 턴에 들어가는 양은 상시 + 키워드로 걸린 항목을 합쳐 **8개·2,500자**까지(`src/js/core/constants.js` LORE — 넘치는 항목은 자르지 않고 그 턴에 빠짐). 상시 항목에는 `not`·`also`를 쓸 수 없어요. `kind`는 항목 종류 — `person` 인물 · `creature` 동물·존재 · `place` 장소 · `item` 물건 · `event` 사건 · `group` 세력 · `concept` 설정(앱의 `LORE_KINDS`, 상세 페이지 세계관 카드의 머리표). `tags`는 그 항목을 그릴 영문 낱말(앱 밖에서 `lore-<n>` 그림을 만들 때). 둘 다 빠지면 빌드 경고 |
| `artTags` | 그 세계관의 영문 낱말(시대·장소·조명·분위기, 예: `joseon dynasty, korean royal palace, paper lanterns, night`). 앱 밖에서 표지·세계관 일러스트를 만들 때 붙여 작품마다 분위기를 맞춰요 |
| `openings[].place`·`suggestions`·`lead` | 시작 상황의 선택 칸. `place`는 **배경 장소** — `places`의 n번째 번호(1부터): 새 대화의 첫 장면 맨 위에 그 장소 카드(`[[MP<n>]]`)가 붙고 상세 페이지의 시작 상황 카드에 장소 이름이 보여요(본문에 이미 그 태그를 적었으면 한 번만). `suggestions`는 **첫 답변 추천** — 독자가 첫마디를 고르기 쉽게 1~3개, 각 40자 이내('✦ AI 추천'을 누르면 AI 호출 없이 보임). `lead`는 **시작 연출** `{ text, turns }` — 이야기를 연 뒤 `turns`턴(1~20) 동안만 AI에 주는 지시(500자 이내). `directive`는 방이 끝날 때까지 가고, `lead`는 도입부에만(예: "처음 세 턴은 사건을 일으키지 말고 인물 소개에 쓴다") |
| `openings[].id` | **시작 상황 id(필수)** — 영문 소문자로 시작하는 소문자·숫자·하이픈 2~24자(`first-night`·`tea-party`), 작품 안에서 겹치지 않게. 화면에는 보이지 않고, 대화방이 시작 상황을 **제목이 아니라 이 id로** 기억해요('처음부터 다시'가 같은 시작 상황을 찾을 때). 그래서 `title`은 언제든 고쳐도 되지만 **id는 한 번 공개하면 고치지 않아요**(이 칸이 생기기 전에 만든 방은 제목으로 찾아요) |
| `openings` | 시작 상황(게임 모드). 인물이 처음 등장하는 줄 위에 `[[코드0]]`(예: `[[KAS0]]` — 코드가 `cast`에 있고 번호가 0~14인지 빌드가 검사). 예전 `[[img:코드:번호]]` 모양은 더 쓰지 않아요 |

`work.js` 안에서는 `const`로 같이 쓸 값을 만들거나(`m/godseats/work.js`의 상태창), 다른 파일을 `import`해도 돼요(예: 키워드북이 길면 `lore.js`로 빼서 `import lore from "./lore.js"`). 빌드가 Node에서 실행한 **결과 값**만 `index.html`에 넣어요 — 그래서 함수 같은 건 넣을 수 없고 글·숫자·참거짓·배열·객체만 돼요.

## 그림 코드 체계

그림 하나 = 코드 한 토큰이에요(2026-11-08, 참고 사이트의 `RIA2`식 구성을 따름).

| 코드 | 뜻 | 보기 |
|---|---|---|
| `<인물코드><번호>` | 그 인물의 감정·행동 칸 그림. 인물 코드는 `cast[].code`(영문 대문자 1~4자), 번호는 0~14 | `HSY3` = 한서윤 · 3 부끄러움 |
| `MP<n>` | 장소 — `places`의 n번째(1부터) | `MP1` |
| `EV<n>` | 컷씬 — `cuts`의 n번째(1부터) | `EV2` |

- 감정·행동 번호(`src/js/core/constants.js`의 `SIT`): 0 프로필 · 1 기본 · 2 웃음 · 3 부끄러움 · 4 슬픔 · 5 놀람 · 6 분노 · 7 삐침 · 8 공포 · 9 부상 · 10 회복 · 11 휴식 · 12 공격(맨손·무기 모두) · 13 각성 · 14 설렘. 모든 인물이 같은 표를 써요
- 다른 모습(폼)은 번호가 아니라 **다른 인물 코드**예요(`cast`에 `of: "본체 코드"`로 한 명 더) — 어린 모습·짐승 모습·가면처럼 생김새가 통째로 바뀔 때. 감정이 바뀌는 건 번호로
- 본문에서는 `[[HSY3]]`처럼 대괄호 둘로 감싸요(AI가 쓰고, 앱이 그림으로 바꿈). 코드를 해석하는 곳(프롬프트·렌더러·갤러리·빌드 검사·도감)은 모두 `src/js/images/codes.js`의 `codebook(작품)` 하나를 써요 — 시리즈를 더하려면 `SERIES`에 한 줄
- 명령어는 두 층이에요. **앱 명령어**(`src/js/core/commands.js` APP_COMMANDS)는 어느 작품에서나 쓰는 공통 명령어로, 화면형 `!상태창`·`!갤러리`·`!지도`·`!도움말`은 AI를 부르지 않고 앱이 처리하고(배지 '앱'), 연출형 `!시간경과`·`!새사건`·`!조연등장`·`!반복금지`는 AI에 공통 연출 지시를 보내요(배지 '연출'). **작품 명령어**(`commands`)는 그 작품의 이야기 장치로 AI에 연출 지시를 보내요(배지 '이야기'). 모두 상세 페이지·도감의 '명령어' 카드에 보이고, 대화방 입력창에 `!`를 치면 목록으로 떠서 고를 수 있어요 — 작품은 `commands`만 적으면 돼요. 독자는 이름 뒤에 말을 덧붙일 수 있고(`!다과회 공작 부인을 부른다`), 연출·이야기 명령어면 AI에 `덧붙인 말: 「…」`로 함께 가요(화면형·즉답은 덧붙인 말을 쓰지 않음) — 그래서 `prompt`에 "덧붙인 말에 대상이 없으면 …"처럼 덧붙인 말이 있을 때와 없을 때를 같이 적어 두면 좋아요
- **도감 메뉴**(`#codex`, `src/js/ui/codex.js`)가 이 체계를 사용자에게 보여 줘요 — 그림 코드 읽는 법·감정 칸 0~14 표·공통 명령어(앱·연출), 그리고 작품을 골라 인물 카드(누르면 코드·외형·`desc` 소개·다른 모습 칩·감정 칸 칩과 미리보기)·장소·컷씬·작품 명령어. 상세 페이지의 등장인물 칸에서도 같은 시트가 열리고 '도감' 버튼이 `#codex-<id>`로 가요. 새 칸(`places`·`cuts`·`commands`·`desc`·`guide`·`hidden`·`creator`·`publishedAt`·`exclusive`)을 채우면 따로 손대지 않아도 도감에 바로 나와요
- 예전 체계(`[[img:p1:3]]`·`p1-3.webp`·조합 `3,404,501`)는 더 쓰지 않아요. 예전 대화방은 열 때 앱이 새 코드로 바꿔요(`core/rooms.js` migrateRoom — 같은 이름의 인물을 지금 작품에서 찾음)

## 그림 싣기 — `images/`

앱은 그림을 만들지 않아요(2026-11-08 정리 때 그림 생성 코드를 걷어 냄 — 예전 코드는 태그 `archive/before-reset-2026-11-08`). 그림은 앱 밖에서 만들고(남성향 일상 화풍의 설정·완성 프롬프트는 [`archive/style-mdaily/`](../archive/style-mdaily/)), 작품 폴더의 `images/`에 **코드 이름 그대로** 넣은 뒤 `npm run build`하면 사용자 사이트에 실려요.

```
content/<f|m|all>/[<줄>/]<id>/images/
  <인물코드><번호>.webp     그 인물의 감정 칸 그림, 번호는 0~14 (예: KAS0.webp 프로필, KAS3.webp 부끄러움)
  MP<n>.webp                places의 n번째 장소 (예: MP1.webp)
  EV<n>.webp                cuts의 n번째 컷씬 (예: EV1.webp)
  cover.webp                대표 일러스트(표지)
  lore-<n>.webp             키워드북 n번째 항목의 세계관 일러스트(1부터)
```

**어떤 그림이 필요한지는 `npm run content:art`** 가 뽑아 줘요(그림 의뢰 목록 — `tools/content-art.mjs`, 먼저 `npm run build`). 한 줄이 그림 한 장이고, 코드(곧 파일 이름)·종류·이름·비공개 여부·우선순위·이미 실렸는지·넣을 경로·그림용 영문 태그가 적혔는지를 보여 줘요. `--work <작품 id>`(한 작품만)·`--todo`(안 실린 것만)·`--rank 1`(그 순위만)·`--json`. 우선순위는 **1** 표지·인물의 프로필(0)과 기본(1)·시작 상황과 즉답 명령어 글에 직접 나오는 그림·시작 상황의 배경 장소 / **2** 나머지 장소·컷씬·인물의 감정 칸·다른 모습의 프로필과 기본 / **3** 다른 모습의 감정 칸·세계관 일러스트(2026-11-11 사용자 결정).

**규격 표 — 확정**(2026-11-11 이미지 세션 — 크기는 화면 자리의 비율과 정확히 같게, 넓이는 그림 모델의 기본 해상도(약 100만 화소) 가까이, 생성 시험으로 확인). 값의 출처는 `tools/content-art.mjs`의 `ART_SPECS` 한 곳이고 도구가 같은 표를 머리에 찍어요(여기를 고치면 그쪽도 — 단위 시험이 두 곳의 크기가 같은지 봐요).

형식은 모두 webp, 투명 배경 없음. 빌드는 그림의 크기·비율을 검사하지 않아요 — 규격과 다른 그림도 실리지만 화면 자리에서 가장자리가 잘리거나 여백이 생겨요.

- 확장자는 webp·png·jpg. 인물 코드는 `cast`의 대문자 그대로, 번호 15 이상·`places`/`cuts` 범위 밖·예전 이름(`ks-0.webp`)은 빌드 실패
- 대화에서 그 칸 그림이 없으면 1 기본 → 0 프로필 순으로 대신 보여 주고, 그것도 없으면 글자 카드예요. 그러니 인물마다 0·1부터 채우면 빈 칸이 안 보여요. 장소·컷씬은 그 번호 그림만(없으면 이름이 든 카드)
- 빌드가 `ORIGINALS`의 `images`(코드 글자 → 번호 → `content/…` 상대 경로)·`img`·`loreImages`에 넣고, 앱은 그 경로를 `<img src>`로 그대로 써요(GitHub Pages·file:// 모두 같은 폴더 구조). claude.ai에 올릴 땐 `content/**/images/`도 함께 올려야 해요
- 그림도 공개 저장소에 들어가요 — 모든 그림은 전체이용가로

## 빌드가 검사하는 것

- 폴더: `f`·`m`·`all` 말고 다른 맨 위 폴더, `work.js`도 `_row.json`도 없는 폴더, 줄 안의 줄
- `id`가 폴더 이름과 같은지, 전체에서 겹치지 않는지
- `aud`·`row`를 적었다면 폴더와 같은지
- **순서 잠금**(`lock.json`): 공개된 장소·컷씬·키워드북의 자리가 그대로인지(중간에 끼우기·지우기·순서 바꾸기는 실패), 시작 상황 `id`·인물 `code`가 없어지지 않았는지 — 위 '순서 잠금'. 장소 이름·컷씬 제목·키워드북의 첫 키가 작품 안에서 겹치지 않는지
- **출연진 성별과 폴더**: 출연진 외모가 모두 여성인데 `f/`에, 모두 남성인데 `m/`에 있으면 실패(남녀가 섞인 작품은 그대로 둠 — 앱의 `guessAud`와 같은 규칙)
- **미성년 인물**: 출연진 외모·설정 첫머리에 19세 미만 나이나 학생 신분이 있으면 실패(앱의 `minorFlags`와 같은 코드)
- 필수 칸(`name`·`title`·`oneLiner`·`desc`·`persona`·`openings`), `cat`·`pal`·`motif` 값, `guide`(플레이 가이드)가 1,000자 이내의 글인지, `noteTemplate`(유저노트 양식)이 2,000자 이내의 글인지, `recommend`(권장 모델)가 `lite`·`story`·`master` 중 하나인지, `creator`가 글·`exclusive`가 참거짓·`publishedAt`이 `YYYY-MM-DD` 모양의 실제 날짜인지
- `cast[].code`가 영문 대문자 1~4자(숫자 없이, `MP`·`EV` 아님)이고 겹치지 않는지, `of`가 본체 인물의 코드인지(폼의 폼은 안 됨), `desc`가 글인지, `hidden`(비공개 감정 번호)이 1~14 정수 배열이고 겹치지 않는지(0 프로필은 실패), `places`·`cuts` 모양(`hidden`은 참거짓), `commands`의 `cmd`가 공백·`!` 없이 겹치지 않고 앱 명령어 이름이 아닌지·`prompt`와 `text` 중 하나만 있는지·`text`가 1,000자 이내이고 그 안의 그림 태그가 맞는지
- 시작 상황의 `id`: 있는지, 모양(영문 소문자로 시작하는 소문자·숫자·하이픈 2~24자)이 맞는지, 작품 안에서 겹치지 않는지
- 시작 상황의 선택 칸: `place`가 `places` 범위 안의 번호인지, `suggestions`가 글 1~3개·각 40자 이내인지, `lead`가 `{ text(500자 이내), turns(1~20) }`인지
- 시작 상황의 `[[코드번호]]`: 코드가 `cast`(또는 `MP`·`EV`)에 있고 번호가 범위 안인지. 예전 `[[img:…]]` 모양은 실패
- `images/`: 파일 이름이 `<코드><번호>`·`cover`·`lore-<n>`인지, 코드와 번호가 위 규칙에 맞는지, 같은 그림·표지가 둘인지, `lore-<n>`이 키워드북 범위 안인지
- 키워드북 규칙: `always`가 참거짓·`order`가 숫자·`not`/`also`가 글 배열인지, 상시 항목에 `not`·`also`를 썼는지, 한 항목의 `text`가 한 턴 예산(2,500자)보다 긴지, 상시 항목의 합이 예산(8개·2,500자)을 넘는지(절반을 넘으면 경고)
- 키워드북 `kind`가 `LORE_KINDS`에 없거나, `cast[].tags`·`lookTags`·키워드북 `tags`·`artTags`에 한글이 있으면 실패
- 경고만: 키워드북 항목에 `kind`·`tags`가 없음, `gauge`가 `fields`에 없음, 시작 상황 `status`의 칸이 `fields`에 없음, `cast`가 있는데 `lookTags`를 씀, 작품이 없는 줄, `images/`의 그림이 아닌 파일·모르는 파일 이름, 남아 있는 `content/codes.json`
